# Require

Loads the given module. The function starts by indexing the loaded table to determine whether `modname` is already loaded. If it is, then `require` returns the value stored at `loaded[modname]`.
    - Module names are the path to a file relative to the resource.
    - The module name must point to a `.lua` file.
    - Use `.` to separate directories in a path.
    - Modules can be loaded from external resources using `@resource.modname`.

## Examples

```lua
require '@resource.client.modname'
```

<Callout type="warning">
    Client modules must be defined in the `file` section of the resource manifest.
    ```lua
        file 'modname.lua'
        -- or
        files {
        'modname.lua'
        }
    ```
</Callout>

> Credit to [Overextended](https://overextended.dev/ox_lib/Modules/Require/Shared) for the documentation.

## ESX.load

Loads and runs a Lua file at the given path relative to the calling resource. Unlike `require`, the chunk is **not** cached for future use.

**Arguments**
- filePath: `string`
  - The path to the file. Use `.` to separate directories.

**Example**
```lua
ESX.load('modules.myModule') -- loads and runs modules/myModule.lua
```

## ESX.loadJson

Loads and decodes a `.json` file at the given path relative to the calling resource.

**Arguments**
- filePath: `string`
  - Path to the JSON file (without the `.json` extension).

**Returns**
- data: `table`
  - The decoded JSON table.

**Example**
```lua
local data = ESX.loadJson('config.test')
```

## ESX.require

Loads the given module and caches the result. Passing `@resourceName.modName` loads a module from a remote resource.

**Arguments**
- modName: `string`
  - The module name. Use `/` separators for relative paths.

**Returns**
- module: `unknown`
  - The loaded module (any value returned by the module).
